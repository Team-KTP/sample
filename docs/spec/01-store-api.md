# 01. 가게 API

- 상태: 제안 (AI가 제안. 샘플 전용의 가짜 정책이다)

시스템이 무엇을 하는지와 API의 모양만 쓴다. 클래스, 테이블, 처리 순서는 쓰지 않는다. 응답의 공통 모양은 서버의 ADR-0007을 따른다.

## API

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| POST | `/products` | 상품 등록 |
| GET | `/products/{productId}` | 상품 조회 |
| PUT | `/products/{productId}/price` | 상품 가격 수정 |
| POST | `/orders` | 주문 |
| GET | `/orders/{orderId}` | 주문 조회 |
| POST | `/orders/{orderId}/cancel` | 주문 취소 |

## 수용 기준

| ID | 기준 | 근거 |
|---|---|---|
| AC-1.1 | 상품을 등록하면 등록한 상품(id, 이름, 설명, 재고, 가격, 품절 여부, 배송비, 출고 소요일)을 돌려준다 | R-1.2, R-1.3, R-1.12 |
| AC-1.2 | 상품 이름이나 설명이 비었거나, 재고, 가격, 배송비가 음수이거나, 출고 소요일이 1보다 작은 등록 요청은 `DEFAULT_VALIDATION_FAILED`(400)와 필드별 사유로 거절한다 | R-1.1, R-1.2, R-1.3, R-1.12, R-1.13, R-1.14 |
| AC-1.3 | 상품을 id로 조회한다. 없으면 `PRODUCT_NOT_FOUND`(404)다 | 기술 결정 |
| AC-1.4 | 주문하면 주문(id, 상태, 수량, 주문 금액, 주문 시각, 상품 id, 받는 사람)을 돌려주고 재고가 준다 | R-1.7, R-1.8 |
| AC-1.5 | 재고보다 많이 주문하면 `PRODUCT_OUT_OF_STOCK`(409)로 거절한다 | R-1.6 |
| AC-1.6 | 주문 수량이 1보다 작거나 받는 사람의 값이 빠진 주문 요청은 `DEFAULT_VALIDATION_FAILED`(400)로 거절한다 | R-1.5, R-1.15 |
| AC-1.7 | 주문을 id로 조회한다. 없으면 `ORDER_NOT_FOUND`(404)다 | 기술 결정 |
| AC-1.8 | 주문을 취소하면 주문 상태가 취소됨이 되고 재고가 돌아온다 | R-1.9 |
| AC-1.9 | 이미 취소한 주문을 취소하면 `ORDER_ALREADY_CANCELED`(409)로 거절한다 | R-1.10 |
| AC-1.10 | 없는 상품을 주문하면 `PRODUCT_NOT_FOUND`(404)로 거절한다 | 기술 결정 |
| AC-1.11 | 같은 상품에 주문이 동시에 들어와도 재고만큼만 주문이 성공한다 | R-1.11 |
| AC-1.12 | 상품의 가격을 수정하면 가격이 바뀐다. 응답 데이터는 없다. 없는 상품이면 `PRODUCT_NOT_FOUND`(404)다 | R-1.1 |
| AC-1.13 | 음수 가격으로 수정하는 요청은 `DEFAULT_VALIDATION_FAILED`(400)로 거절한다 | R-1.1 |

## 기술 결정

- 성공 응답의 HTTP 상태는 모두 200이다(서버의 기준 코드와 같다).
- 없는 대상의 조회는 404와 대상별 오류 코드다.
